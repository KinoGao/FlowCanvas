## 3. 三个产品的交互模型

| 维度 | LibTV | TapNow | 小云雀 | FlowCanvas 应吸收的重点 |
|---|---|---|---|---|
| 核心空间 | 无限画布 + 工作流创作 | 无限画布 + 节点关系 | Agent 驱动的内容/短剧生产 | 画布是生产空间，Agent 是入口和编排层 |
| 用户第一步 | 新建画布、能力入口、工作流 | 空白画布、添加节点、Agent | 输入灵感或开始创作 | 空白画布必须能立即创建，也要能用自然语言启动 |
| 主要关系 | 以内容生产链路组织 | 节点与连线表达引用关系 | 以剧本、镜头、成片阶段组织 | 节点关系要可见，故事阶段也要可追踪 |
| 结果处理 | 生成能力和工作流复用 | 结果追加为新节点，来源保留 | 目标是成片和可继续编辑的工作流 | 生成不能覆盖来源；每次生成都应可回溯 |
| 低门槛入口 | Skill / 功能卡 / Agent | Agent + 节点菜单 | 灵感输入 + 内容模板 | `/`、Skill、模板和 Agent 统一到当前上下文 |
| 复杂度控制 | 通过工作流包装复杂能力 | 通过节点、引用和 Agent 展开 | 通过剧本/短剧生产流程展开 | 默认简单，展开后保持可检查和可撤销 |

结论不是“三选一”：FlowCanvas 的基础交互应以 TapNow 的画布契约为基准，创作入口和媒体工作流参考 LibTV，小云雀则提供“从灵感到故事、镜头、成片”的 Agent 层组织方式。

## 4. TapNow：需要逐项对齐的画布契约

### 4.1 视口手势

官方画布文档给出的行为是：

| 操作 | TapNow 行为 | 交互含义 |
|---|---|---|
| 鼠标滚轮 / 触控板双指滑动 | 平移画布 | 普通滚轮不是缩放，视口移动是默认行为 |
| 触控板捏合 | 缩放 | 缩放以光标/手势中心为锚点 |
| Cmd/Ctrl + 滚轮 | 缩放 | 给鼠标用户一个显式缩放通道 |
| 左下角缩放控件 | 放大、缩小、显示当前比例 | 低成本的可发现性和恢复入口 |
| Cmd/Ctrl + `+` / `-` | 缩放 | 键盘缩放不依赖鼠标位置 |
| 中键拖拽 | 平移 | 适合桌面鼠标 |
| 右键拖拽 | 平移 | 需要避免与空白区上下文菜单冲突 |
| 左键拖拽空白区 | 框选 | 空白区左拖不是平移，避免误移动整个画布 |
| 点击空白区 | 取消选中 | 结束当前节点操作状态 |

这组规则的关键不是某一个快捷键，而是“左键负责选择、其他手势负责视口”的分工。任何一个手势被两个功能抢占，都会造成用户无法预测操作结果。

### 4.2 添加节点

TapNow 的添加入口有三种等价路径：

- 点击画布上的 `+` 菜单。
- 在空白位置双击，在指针位置打开创建菜单。
- 在空白区域右键，在指针位置打开创建菜单。

文件可以从添加菜单上传，也可以直接拖到画布。创建菜单应以“节点类型”组织，而不是让用户先理解模型、参数和工作流内部结构。节点落点应是指针所在位置；如果菜单打开后画布发生平移或缩放，仍应使用稳定的画布坐标，而不是屏幕坐标。

### 4.3 选中和多选

- 点击节点：选中一个节点。
- Shift 点击：追加或移除选中项。
- 在空白区左键拖拽：框选多个节点。
- 多选后的移动、删除、复制、分组和对齐必须作用于整个选区。
- 节点被选中后，节点右侧的 `+` 是上下文添加入口。

节点右侧 `+` 的特殊价值是把“创建”放进了当前工作流：选择节点类型后，新节点自动接入当前节点。多选后从选区右侧 `+` 创建时，新节点可以同时接收选区内节点的引用关系，减少手工拉线。

### 4.4 连线和引用

TapNow 的连线不是装饰线，而是下游节点读取上游内容的引用关系：

1. 从源节点右侧连接点拖向目标节点。
2. 松开后，只有类型合法的连接才保留。
3. 下游提示词或输入区使用 `@` 选择上游节点作为参考。
4. 生成前检查引用是否正确，避免只看到了线却没有真正使用素材。
5. 删除连接只删除关系，不删除两端节点。

从节点连接点拖到空白区时，创建菜单可以直接接在拖拽终点；选定类型后，新节点和连接一起完成。这比“先创建节点、再寻找连接点”更符合工作流的连续操作。

### 4.5 节点结果和来源

生成结果应追加为新节点，原节点继续保留。这样可以：

- 对比不同提示词、模型和参数的结果。
- 回到上一个版本重新生成。
- 把同一素材接到多个下游分支。
- 在画布上看见“素材从哪里来、结果如何产生”。

“覆盖当前节点”只能作为明确的替换动作，不能作为默认生成行为。

### 4.6 删除、撤销和可恢复性

- 删除节点前应有明确的选中态；删除连线不应连带删除节点。
- Delete / Backspace 删除选中项。
- Cmd/Ctrl + Z 撤销，Cmd/Ctrl + Shift + Z 或 Cmd/Ctrl + Y 重做。
- 粘贴、复制、移动、连线、分组和节点参数修改都应进入同一撤销栈。
- 生成任务进行中删除节点时，应明确显示任务是否取消、结果是否仍会回写。

### 4.7 Minimap 和视图恢复

画布需要同时提供：

- Fit view：将所有节点纳入可见区域。
- Minimap：点击跳转，拖动视口框快速定位。
- 当前缩放比例：可读、可恢复，不只是一个装饰数字。
- Reset view：恢复默认中心和比例。

视图操作不应改变节点选中状态，节点编辑也不应导致视口无意义跳动。

### 4.8 Agent 生命周期

TapNow 官方 Agent 文档呈现的核心链路是：读取上下文 → 确认目标 → 制定计划 → 执行 → 根据反馈修订 → 交付。高成本或有外部影响的动作应在执行前确认，例如大批量生成、发布、同步和覆盖已有结果。

对 FlowCanvas 的直接要求：

- Agent 读取当前画布、选中节点、连线和素材引用，而不是只读取聊天文本。
- Agent 生成前展示模型、数量、比例、时长和参考素材等关键参数。
- 用户确认的是“即将发生的动作”，而不是一个笼统的“确定执行”。
- 任务过程中可看到队列、进行中、成功、失败和可重试状态。
- Agent 生成的节点和连线进入撤销栈，并能说明变更范围。

## 5. LibTV：生产工作流和入口层

LibTV 的公开信息更适合用来研究“如何让创作开始”和“如何把复杂能力包装起来”，不适合在未登录状态下强行推断每个画布手势。

### 5.1 值得借鉴的结构

- 以无限画布承载图片、视频、音频、文本和脚本等媒体生产链路。
- 把复杂创作能力包装成工作流、Skill 或快捷能力，让用户从目标开始，而不是从参数表开始。
- 允许把一组节点保存成模板，在新的画布中复用。
- 通过分镜、剧情和镜头等生产概念组织媒体节点，降低纯节点图的抽象感。
- Agent 入口应该能理解当前画布上下文，而不是独立于画布的聊天窗口。

### 5.2 不应直接照搬的部分

- 积分、会员、付费模型、社区发布和创作者激励不在 FlowCanvas v1 范围。
- 首页内容卡片不能挤占画布中的节点操作空间。
- “一键能力”不能隐藏模型、引用素材和生成参数，否则失败后无法解释。
- 不能把登录后未核验的交互细节写成 FlowCanvas 的硬性实现依据。

### 5.3 FlowCanvas 对应设计

保留画布的低视觉重量，用中心空态、节点右侧 `+`、`/` 快捷入口和 Agent 面板承担启动任务；复杂流程以“脚本 / 分镜 / 工作流组”显示语义，但底层仍然是可见、可复制、可撤销的节点和连线。

## 6. 小云雀：从灵感到成片的 Agent 组织

小云雀公开首页给出的信号与 TapNow 不同：它首先让用户表达灵感或选择创作方向，再进入短剧、视频和营销内容生产。页面展示了“观看全片”和“查看工作流”等入口，并覆盖剧本解析、故事广告、角色/三视图、分镜、品牌片、知识视频和字幕处理等内容能力。

### 6.1 可以确认的交互方向

- 入口应允许自然语言输入灵感，不要求用户先创建节点。
- 系统应把长内容拆成可理解的阶段：故事、角色、场景、分镜、片段、成片。
- 用户需要能从成片结果回看工作流，理解结果由哪些步骤组成。
- 多个视频或镜头之间要有连续性提示，而不是只展示一组孤立生成结果。
- Agent 应该把复杂任务拆成可确认的阶段，允许用户在剧本、角色、分镜和生成之间插入修改。

### 6.2 尚不能确认的内容

- 公开页面不能证明小云雀使用与 TapNow 相同的无限画布平移、缩放、框选和连线规则。
- “导演台 / 3D 场景编辑器”等二手资料只能作为产品方向线索，不能当作小云雀通用画布的交互证据。
- 不应因为页面有“查看工作流”就假设用户可以自由编辑所有节点关系。

### 6.3 FlowCanvas 应吸收的层级

小云雀适合作为 FlowCanvas 的“创作叙事层”：用户可以输入一句灵感，Agent 在当前画布中生成脚本节点、角色节点、分镜组和媒体生成节点；用户仍能回到节点层检查每一步。这样既保留无限画布的可控性，也避免新用户面对空白画布时不知道从哪里开始。

## 7. FlowCanvas 当前实现核验

以下内容来自当前仓库代码和本地画布现场操作，不是计划中的功能承诺。

### 7.1 已有基础能力

- 多选、框选、节点分组、故事板组和工作流模板。
- 跨画布复制，保留节点和连线关系。
- Minimap、Fit view、Reset view、对齐辅助线和吸附。
- 节点右侧快速创建；从连接点拖向空白区后创建节点并自动连接。
- 节点悬浮工具栏、创建菜单、媒体节点和 Agent 入口。
- 后端账号工作区持久化，画布和生成记录不依赖浏览器本地业务缓存。

### 7.2 代码位置

| 主题 | 当前文件 | 核验重点 |
|---|---|---|
| 键盘事件 | `web/src/app/(user)/canvas/[id]/canvas-client-page.tsx` | 约 2398 行处理撤销、重做、全选、复制、粘贴、缩放、分组、删除、Escape 等 |
| 画布手势 | `web/src/app/(user)/canvas/components/leafer-canvas.tsx` | 约 647、679 行配置多选、wheel 和 Space/中键移动 |
| 快捷键面板 | `web/src/app/(user)/canvas/components/canvas-toolbar.tsx` | 约 407 行列出快捷键和交互承诺 |
| 节点右键菜单 | `web/src/app/(user)/canvas/components/canvas-context-menu.tsx` | 当前主要是 Duplicate / Delete |
| 空白区创建菜单 | `web/src/app/(user)/canvas/components/canvas-create-node-menu.tsx` | 双击、右键、添加按钮、拖入文件和多种节点类型 |
| 节点二次点击 | `web/src/app/(user)/canvas/[id]/canvas-client-page.tsx` | 图片节点首次点击选中，短时间内再次点击打开 Composer，继续点击预览 |

### 7.3 现场核验到的真实差距

本地画布 `http://localhost:9800/canvas/QC5zERCaj5bqhMazT7wWh` 的现场操作记录如下：

| 操作 | 实际结果 | 结论 |
|---|---|---|
| 普通鼠标滚轮 | 画布比例从 100% 变为 83% | 当前默认是缩放，与 TapNow“滚轮平移、Ctrl/Cmd+滚轮缩放”的契约不一致 |
| Reset view | 恢复到 100% | 视图恢复入口有效 |
| 选中图片节点后 Ctrl+D | 节点数量仍为 1 | 快捷键面板中的复制快捷键未形成可用闭环，需实现或移除承诺 |
| 画布按 Tab | 未创建节点 | 如果产品要保留 Tab 快捷创建，需要接入真实处理；否则不应只展示在面板中 |

### 7.4 快捷键面板与处理器不一致

快捷键面板目前列出 `Ctrl+D`、`Ctrl+Enter`、`Tab`、`Ctrl+L`、`Alt+Shift+F`、Alt 拖拽复制和 Ctrl+Alt 拖拽复制等操作，但键盘处理器现场能确认的主要是 `Ctrl/Cmd+Z`、`Y`、`A`、`C`、`V`、`+`、`-`、`0`、`S`、`P`、`J`、`F`、分组、删除和 Escape。

这不是单纯的文案问题：快捷键面板是交互协议的一部分。用户按下一个可见快捷键后没有反馈，会降低对整个画布的信任。应先建立“面板条目—事件处理—撤销栈—现场测试”的一一对应关系，再补充更多快捷键。

## 8. FlowCanvas 的优先级差距清单

### P0：先修正画布物理交互

1. 明确普通滚轮、Ctrl/Cmd+滚轮、触控板捏合、Space/中键拖拽、右键拖拽和空白区左键框选的互斥关系。
2. 缩放以指针所在画布坐标为锚点；连续滚轮不能造成视口跳动。
3. 空白区右键菜单和右键平移要有可预测的判定：短按打开菜单，拖动超过阈值进入平移。
4. 框选过程中不能误触发画布平移；框选结束后保留选区和可见的主选中态。
5. 让快捷键面板只展示已实现且可测试的动作，或逐项补齐实现。

### P0：补齐节点级反馈

1. 节点右侧 `+`、连接点、悬浮工具栏、选中边框和拖拽预览应有明确的 hover / active / invalid 状态。
2. 连线拖到非法目标时显示不可连接状态，松开后不留下半条线。
3. 从连接点拖到空白区创建节点时，菜单锚点、连接预览和创建后的自动连线要保持连续。
4. 删除连线和删除节点要分开确认；删除结果可撤销。
5. 生成结果默认追加新节点，不覆盖来源节点；生成中节点显示进行中、失败和重试状态。

### P1：让工作流关系可读、可复用

1. 下游节点明确展示引用了哪些上游节点，不能只依赖一条细连线。
2. `@` 引用选择器、连接线和输入字段保持同步，删除引用时给出影响提示。
3. 多选后复制、粘贴、拖拽复制、分组、对齐和跨画布复制统一进入撤销栈。
4. 工作流组保存为模板时显示包含的节点、连线和外部依赖；插入模板时避免与现有节点重叠。
5. Minimap、Fit view、Reset view 和缩放比例在深浅主题下保持高可见度但低干扰。

### P1：Agent 需要可检查的执行过程

1. Agent 执行前读取当前选区、输入、连线和媒体引用。
2. 生成前确认模型、数量、比例、时长、参考素材和预计影响范围。
3. 批量生成、覆盖、发布、同步等动作提供逐项确认；普通节点整理不应频繁打断。
4. Agent 创建的节点和连线显示来源，并可整体撤销或按阶段撤销。
5. 失败时保留输入和错误原因，允许修改参数后重试，不要让用户重新搭建链路。

### P2：吸收小云雀的故事层

1. 空白画布增加“输入灵感”入口，生成脚本 / 角色 / 场景 / 分镜的初始工作流。
2. 以脚本、分镜组和成片状态展示生产阶段，但不隐藏底层节点。
3. 支持从一个故事阶段继续生成下一阶段，也支持回到任意阶段分叉。
4. 将“查看工作流”做成可读的只读检查视图，再提供明确的编辑入口。

## 9. 建议的验收用例

### 9.1 视口和选择

- 普通鼠标滚轮只平移；Ctrl/Cmd+滚轮缩放。
- 触控板双指滑动平移，捏合缩放。
- Space + 左键、中键拖拽和右键拖拽均可平移；右键短按仍能打开菜单。
- 空白区左拖只框选；框选后移动只移动选中节点。
- 缩放前后，指针下的画布内容位置稳定。
- Fit view、Reset view、Minimap 跳转不会意外改变选中态。

### 9.2 节点和连线

- 双击空白区、空白区右键、创建按钮都在正确的画布坐标打开菜单。
- 从节点右侧 `+` 创建下游节点并自动连线。
- 从连接点拖到空白区创建节点并自动连线。
- 非法连接有明确反馈，松开后无残留。
- 删除连线不删除节点；删除节点后关联线清理；两者都可撤销。
- 生成结果追加新节点，来源仍可重新生成。

### 9.3 快捷键和 Agent

- 面板中的每一个快捷键都能现场触发，并在画布上给出反馈。
- Ctrl/Cmd+D、Ctrl/Cmd+Enter、Tab、Ctrl/Cmd+L、Alt+Shift+F 逐项测试。
- 节点复制、移动、连线、分组、粘贴和删除都能撤销重做。
- Agent 能读取当前选区并在生成前展示动作计划。
- 批量生成前需要确认；失败后可以在原节点链路上修改并重试。

## 11. 最终判断

FlowCanvas 的核心方向是对的，但当前最需要处理的不是再增加一个节点类型，而是把“画布物理交互”和“可见快捷键承诺”做成可信的协议：用户要知道什么时候是在移动画布、什么时候是在选择节点、什么时候是在建立引用、什么时候 Agent 会真正开始消耗资源。

在这个基础上，再把 LibTV 的生产工作流和小云雀的故事 Agent 入口接到现有节点系统中，才能让无限画布既适合熟练用户编排，也适合第一次打开产品的用户从一句灵感开始。
