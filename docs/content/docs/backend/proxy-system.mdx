# 代理（转发）系统

## 概述

前端直接请求外部服务时可能遇到 **CORS（跨域）** 限制。项目内置三种 Next.js 服务端转发机制来解决此问题：

| 转发类型 | 服务端路由 | 适用场景 |
|---|---|---|
| AI 代理 | `/api/ai-proxy` | AI API 渠道（大模型请求、图片下载） |
| WebDAV 代理 | `/webdav-proxy` | WebDAV 同步 |
| ComfyUI 代理 | `/api/comfyui-proxy` | ComfyUI 工作流 |

每种代理均可由用户在 UI 配置中切换为 **前端直连（direct）** 或 **Next.js 转发（nextjs）**。

---

## AI 代理

### 工作原理

AI 代理逻辑分散在两个工具函数中：

1. **`buildApiUrl(baseUrl, path, useProxy)`** — 构造请求 URL
   - 拼接 baseUrl + `/v1`（如果还没带） + path
   - 如果 `useProxy === true`，返回 `/api/ai-proxy?target=<encodedUrl>` 让请求走服务端
   - 否则直接返回完整 URL 供前端直连

2. **`rewriteThroughProxy(url, useProxy)`** — 仅改写图片/视频等资源的下载 URL
   - 如果 `useProxy === true`，将 URL 改为 `/api/ai-proxy?target=<encodedUrl>`
   - 否则原样返回

### 服务端实现

`web/src/app/api/ai-proxy/route.ts`：

- 接收 `target` 查询参数，调用 `fetch(target, ...)` 透传
- 支持 GET、POST、PUT、DELETE 方法
- 将客户端发送的 `Content-Type`、`Authorization` 等头转发
- 默认 100s 超时

### 渠道级别代理

AI 渠道的 `useProxy` 字段在各服务的构建函数中传递：

```typescript
// 各 service 中的通用模式
function aiApiUrl(config: AiConfig, path: string) {
    return buildApiUrl(config.baseUrl, path, config.useProxy);
}
```

服务中获取图片/视频下载 URL 时也会通过 `rewriteThroughProxy` 处理：

- **image.ts**：`resolveImageDataUrl` 在解析 `b64_json` 或 `url` 时调用 `rewriteThroughProxy(url, useProxy)`
- **image.ts**：`parseGeminiImagePayload` 对 Gemini 返回的 `fileUri` 调用 `rewriteThroughProxy`
- **video.ts**：`pollOpenAIVideoTask`、`pollSeedanceTask`、`pollAgnesVideoTask` 获取视频下载 URL 时调用 `rewriteThroughProxy`

## WebDAV 代理

### 前端实现

`web/src/services/webdav-sync.ts`：

- 通过 `config.proxyMode` 判断
  - `"direct"`：前端直连 WebDAV URL
  - `"nextjs"`：发送 POST 到 `/webdav-proxy`，目标 URL、方法、鉴权头通过自定义 HTTP 头传递：
    - `x-webdav-target`：完整的 WebDAV URL
    - `x-webdav-method`：HTTP 方法
    - `x-webdav-authorization`：Basic Auth
    - `x-webdav-depth`、`x-webdav-destination`、`x-webdav-overwrite`、`x-webdav-content-type`

### 服务端实现

`web/src/app/webdav-proxy/route.ts`：

- Node.js runtime，`force-dynamic`
- 从 `x-webdav-target` 读取目标 URL，从 `x-webdav-*` 头还原原始请求头
- 120s 超时
- 只返回有限的响应头（`content-type`、`etag`、`last-modified`、`dav`）

## ComfyUI 代理

### 前端实现

`web/src/services/api/comfyui.ts` 中有三种转发场景：

**1. 通用请求（comfyRequest）**
```typescript
config.proxyMode === "nextjs"
    ? fetch("/api/comfyui-proxy", { body: JSON.stringify({ baseUrl, path, method, body }) })
    : fetch(`${baseUrl}${path}`, init)
```

**2. 文件上传（uploadComfyFile）**
```typescript
config.proxyMode === "nextjs"
    ? fetch("/api/comfyui-proxy", { body: formData })  // 附加 baseUrl 字段
    : fetch(`${baseUrl}/upload/image`, { body: formData })
```

**3. 文件查看 URL（buildComfyViewUrl）**
```typescript
config.proxyMode === "nextjs"
    ? `/api/comfyui-proxy?baseUrl=...&path=...`
    : `${baseUrl}${path}`
```

### 服务端实现

`web/src/app/api/comfyui-proxy/route.ts`：

- GET：从查询参数取 `baseUrl`、`path`
- POST（JSON）：从请求体取 `baseUrl`、`path`、`method`、`body`
- POST（multipart）：从 formData 取 `baseUrl`，其余字段透传
- 白名单路径限制：`/system_stats`、`/object_info`、`/prompt`、`/history/`、`/view`、`/upload/image`

## 数据结构

### AIConfig（use-config-store.ts）

```typescript
type AiConfig = {
    baseUrl: string;          // 旧版兼容，新用户不直接使用
    apiKey: string;           // 旧版兼容，新用户不直接使用
    apiFormat: ApiCallFormat; // "openai" | "gemini"
    useProxy?: boolean;       // 旧版兼容，新用户不直接使用
    channelMode: "local";
    channels: ModelChannel[]; // 渠道列表
    // ... 模型选择字段
};
```

### ModelChannel

```typescript
type ModelChannel = {
    id: string;           // 唯一标识（nanoid）
    name: string;         // 显示名称
    baseUrl: string;      // API 地址
    apiKey: string;       // API Key
    apiFormat: ApiCallFormat;
    models: string[];     // 原始模型名列表
    useProxy: boolean;    // true=走 Next.js 转发
};
```

`resolveModelRequestConfig(config, value)` 根据选中的模型值（格式 `channelId||modelName`）查找对应渠道，将 `channel.baseUrl`、`channel.apiKey`、`channel.apiFormat`、`channel.useProxy` 合并到返回的 `AiConfig` 中，各 service 拿到的 `config.useProxy` 来自渠道而非顶层配置。

### WebdavSyncConfig

```typescript
type WebdavSyncConfig = {
    url: string;
    directory: string;
    username: string;
    password: string;
    proxyMode: "direct" | "nextjs";
};
```

### ComfyUiConfig

```typescript
type ComfyUiConfig = {
    baseUrl: string;
    clientId: string;
    proxyMode: "direct" | "nextjs";
    timeoutSeconds: number;
    pollIntervalMs: number;
};
```

## 关键区别

| 特性 | `buildApiUrl` | `rewriteThroughProxy` |
|---|---|---|
| 用途 | 构造 API 请求 URL | 改写资源下载 URL |
| 是否加 `/v1` 前缀 | 是（如需） | 否 |
| 是否处理方舟 Plan URL | 是（`normalizeArkPlanBaseUrl`） | 否 |
| 返回形式 | 完整 URL 或 `/api/ai-proxy?target=` | 原 URL 或 `/api/ai-proxy?target=` |
