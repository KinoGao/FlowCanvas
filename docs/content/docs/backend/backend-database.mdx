# 后端数据库结构

后端使用 SQLite 作为存储引擎，由 Spring Data JPA + Hibernate 自动迁移（`ddl-auto: update`）。数据库文件路径由环境变量 `DB_PATH` 指定，默认为 `./data/app.db`。

## 表结构概述

后端没有全局单行的 `AiConfig` 配置表：平台级配置存在 `platform_config`，每个账号的工作区配置存在 `user_configs`，账号与媒体、画布分别存于其他账号相关表（见下文）。前端不再通过 config 接口做 localStorage last-write-wins 合并。

## 平台凭证

- 注册账号提交 `REGISTRATION_CODE`（`app.registration-code`），未设置时回退到 `AUTH_CODE`（`app.auth-code`），内部部署默认为 `gycode`，可通过环境变量覆盖。
- 管理员登录提交 `ADMIN_CODE`（`app.admin-code`），默认 `admincode`，账号还必须拥有 `ADMIN` 角色；实例尚无管理员时，首个通过管理员授权码登录的有效账号会被初始化为管理员。
- 媒体访问签名密钥 `MEDIA_SIGNING_SECRET`（`app.media-signing-secret`），默认继承 `ADMIN_CODE`，生产应设置随机值。
- 平台配置中托管的厂商 API Key 只保存在后端 `platform_config`，不下载到浏览器。

## platform_config 表

单行存储，固定 `id = 1`。用于后台管理统一保存厂家、后端托管 API Key、模型能力、ComfyUI 地址和工作流运行参数。创作端通过 `/api/runtime-config` 读取脱敏后的发布模型和 ComfyUI 基础能力，不直接读取该表中的密钥。

| 列名 | 类型 | 说明 |
|---|---|---|
| `id` | BIGINT (PK) | 固定值 `1`，单行存储 |
| `data` | TEXT | `PlatformConfigDocument` JSON 字符串，包含 providers、models、comfyui 配置 |
| `updated_at` | TIMESTAMP | 最后一次保存时间 |

### 为什么使用 JSON 文档存储

`data` 是后端的持久化和原子发布格式，不是管理员的编辑界面。模型厂商的鉴权方式、图片/视频/音频模型能力和 ComfyUI 工作流字段差异较大，如果把每一种能力拆成固定数据库列，会频繁改表且难以扩展。保存为一个版本化文档可以一次发布完整配置，避免厂商、模型和默认工作流处于互不匹配的中间状态。

管理员在 `/admin` 中按“厂商连接 -> 拉取模型 -> 分类并配置能力 -> 发布”的顺序维护：

- 厂商连接：填写厂商名称、真实服务地址、API Key、协议、模型列表路径和启用状态。OpenAI 兼容协议默认从 `/models` 读取 `data[].id`，Gemini 协议默认从 `/v1beta/models` 读取 `models[].name`。
- 模型发现：拉取结果只是上游模型候选，不会自动发布。管理员为候选模型设置稳定内部 ID、显示名称、私有 `requestModel`、所属厂商和发布状态。
- 模型分类：每个模型必须归入 `text`、`image`、`video` 之一；同一厂商可以同时拥有三类模型。
- 文本能力：分别配置纯文本和识图/多模态输入能力。
- 图像能力：分别配置文生图、图生图、图像编辑，以及低/标准/高画质、1K/2K/4K、支持比例和 1/2/4 张生成数量。
- 视频能力：分别配置文生视频、全能参考、首帧图生视频（`first_frame`）、首尾帧图生视频（`first_frame` + `last_frame`）、图片参考、智能多帧，以及有声、水印、草稿、时长、分辨率、生成数量和图片/视频/音频引用上限。
- ComfyUI：全局地址、客户端 ID、超时、轮询间隔和默认工作流。
- 工作流：上传原始 ComfyUI API workflow JSON，后台识别输入候选后用表单配置可暴露字段，不要求管理员手写能力 JSON。

该配置是实例级全局配置，对所有登录账号生效。用户账号只保存各自画布、素材、媒体文件和创作偏好，不复制厂商密钥或模型能力配置。

### 使用入口

- `/api/admin/platform-config` 需要带 `ADMIN` 角色的 Bearer 会话，用于后台管理读取和保存完整配置。
- `POST /api/admin/providers/{providerId}/discover-models` 按厂商的协议、`baseUrl`、API Key 和 `modelsPath` 拉取上游模型名；管理员随后逐个分类并映射为稳定内部 ID，发现操作本身不会发布模型。
- `/api/runtime-config` 对创作端开放，只返回满足发布条件的稳定模型 ID、显示信息、模型能力和脱敏后的 ComfyUI 参数，不返回 API Key、真实厂商地址或 `requestModel`。
- `/api/model-runtime/models/{stableModelId}/...` 根据稳定模型 ID 查找厂商和私有 `requestModel`，校验模式、比例、分辨率、时长、数量、音频、水印、样片及引用数量后再转发。
- 普通账号 Bearer token 不能访问 `/api/admin/**`；管理接口只接受管理员会话。

### 账号工作区管理

后台的账号工作区页面用于检查各账号同步状态，不承担画布编辑：

- `GET /api/admin/workspaces` 返回账号、画布标题和更新时间、软删除状态、素材数量、媒体文件数量与总字节数。
- `GET /api/admin/workspaces/{userId}/projects/{projectId}` 只在管理员明确点击查看时返回该画布的完整 JSON。
- `PUT /api/admin/users/{userId}` 可修改用户名、显示名称和角色；`PUT /api/admin/users/{userId}/password` 重置密码并注销该账号的旧会话。
- `DELETE /api/admin/users/{userId}/projects/{projectId}` 删除指定账号画布；`DELETE /api/admin/users/{userId}` 删除账号及其工作区数据，当前管理员不能删除自己。
- 摘要接口使用数据库投影和聚合查询，不加载 `project_json`、`asset_json` 或文件实体列表，避免账号和画布增长后后台首页占用大量内存。

## 账号保存相关表

账号保存模式用于后端账号工作区，也是正常业务的唯一账号存储通道。登录态使用后端签发的 Bearer token；注册账号需要提交 `REGISTRATION_CODE`（默认 `gycode`）。管理员登录额外提交 `ADMIN_CODE`（默认 `admincode`），并且账号必须拥有 `ADMIN` 角色；实例中尚无管理员时，首个通过管理员授权码登录的有效账号会初始化为管理员。旧 `AUTH_CODE` 仅保留给旧配置接口和开发兼容入口，不再作为用户数据或后台管理的共享身份。

### users 表

| 列名 | 类型 | 说明 |
|---|---|---|
| `id` | VARCHAR (PK) | 用户 ID |
| `username` | VARCHAR (unique) | 登录用户名，按小写归一化 |
| `password_hash` | VARCHAR | PBKDF2 哈希后的密码，不保存明文 |
| `display_name` | VARCHAR | 显示名称 |
| `role` | VARCHAR | `USER` 或 `ADMIN`，默认 `USER` |
| `created_at` | TIMESTAMP | 创建时间 |
| `updated_at` | TIMESTAMP | 更新时间 |

### user_sessions 表

| 列名 | 类型 | 说明 |
|---|---|---|
| `id` | VARCHAR (PK) | 会话 ID |
| `user_id` | VARCHAR (FK) | 所属用户 |
| `token_hash` | VARCHAR (unique) | Bearer token 的 SHA-256 哈希 |
| `created_at` | TIMESTAMP | 创建时间 |
| `expires_at` | TIMESTAMP | 过期时间 |

### user_configs 表

每个用户一行，保存该账号工作区的完整用户配置 JSON。全局模型厂商、私有 API Key、请求模型和能力目录由管理员配置管理，不下发到该表或浏览器。

| 列名 | 类型 | 说明 |
|---|---|---|
| `id` | VARCHAR (PK) | 配置记录 ID |
| `user_id` | VARCHAR (unique, FK) | 所属用户 |
| `data` | TEXT | 完整配置 JSON 字符串 |
| `updated_at` | TIMESTAMP | 最后更新时间 |

### canvas_projects 表

按用户保存画布项目。`project_json` 保存前端项目 meta 与 detail 的完整 JSON，后端只抽取 `id`、`title`、时间字段用于列表和覆盖写入。

| 列名 | 类型 | 说明 |
|---|---|---|
| `id` | VARCHAR (PK) | 画布项目 ID |
| `user_id` | VARCHAR (FK) | 所属用户 |
| `title` | VARCHAR | 项目标题 |
| `project_json` | TEXT | 项目完整 JSON |
| `created_at` | TIMESTAMP | 项目创建时间 |
| `updated_at` | TIMESTAMP | 项目更新时间 |
| `deleted_at` | TIMESTAMP nullable | 软删除时间；账号同步删除画布时写入，接口默认不返回已软删除项目 |

### canvas_templates 表

按用户保存画布工作流模板（前端 `CanvasWorkflowTemplate`：`{ id, name, createdAt, nodes, connections }`）。`nodes_json` 与 `connections_json` 分别保存节点数组（`CanvasNodeData[]`）与连线数组（`CanvasConnection[]`）的 JSON 序列化，后端不解析节点内部结构。接口：`GET /api/canvas-templates` 返回当前账号模板列表（按更新时间倒序），`POST /api/canvas-templates` 保存模板（校验 `name` 非空、`nodes`/`connections` 为合法 JSON 数组），`DELETE /api/canvas-templates/{id}` 仅删除当前账号自己的模板。

| 列名 | 类型 | 说明 |
|---|---|---|
| `id` | VARCHAR (PK) | 模板 ID |
| `user_id` | VARCHAR (FK) | 所属用户，接口按账号隔离 |
| `name` | VARCHAR | 模板名称 |
| `nodes_json` | TEXT | 节点数组 JSON |
| `connections_json` | TEXT | 连线数组 JSON |
| `created_at` | TIMESTAMP | 创建时间 |
| `updated_at` | TIMESTAMP | 最后更新时间 |

### agent_runs 表

Agent Run 服务端批量生成任务组（画布 Agent「任务规划」模式确认后创建）。任务列表以 JSON 内嵌在 `tasks_json`（每任务含 id/nodeId/type/prompt/modelId/params/dependencies/status/attempts/error/upstreamTaskId/result），执行状态机由后端 `AgentRunExecutor` 驱动（拓扑派发、视频轮询、产物落盘到 `user_files`）。接口：`POST /api/agent-runs` 创建并启动、`GET /api/agent-runs?projectId=`、`GET /api/agent-runs/{id}`、`POST /api/agent-runs/{id}/pause|resume|cancel`、`POST /api/agent-runs/{id}/tasks/{taskId}/retry`。

| 列名 | 类型 | 说明 |
|---|---|---|
| `id` | VARCHAR (PK) | run ID（前端生成） |
| `user_id` | VARCHAR (FK) | 所属用户，接口按账号隔离 |
| `project_id` | VARCHAR | 所属画布项目 |
| `title` | VARCHAR | 标题 |
| `requirement` | TEXT | 原始需求文本 |
| `plan_json` | TEXT | 创作计划 JSON（简报/视觉方向/产物清单） |
| `tasks_json` | TEXT | 任务数组 JSON（状态机载体） |
| `status` | VARCHAR | RUNNING / PAUSED / COMPLETED / FAILED / CANCELLED |
| `session_token` | VARCHAR | 创建时的会话令牌（执行器自调用模型代理鉴权用） |
| `created_at` | TIMESTAMP | 创建时间 |
| `updated_at` | TIMESTAMP | 最后更新时间 |

### assets 表

按用户保存素材库条目。素材文件本体通过 `user_files` 落盘，素材条目中的 `storageKey` 指向对应文件。

| 列名 | 类型 | 说明 |
|---|---|---|
| `id` | VARCHAR (PK) | 素材 ID |
| `user_id` | VARCHAR (FK) | 所属用户 |
| `asset_json` | TEXT | 素材完整 JSON |
| `updated_at` | TIMESTAMP | 素材更新时间 |

### user_files 表

按用户保存图片、视频、音频等媒体文件元数据，文件本体落盘到 `USER_FILE_DIR` 指定目录，默认 `./data/user-files/{userId}/...`。

| 列名 | 类型 | 说明 |
|---|---|---|
| `id` | VARCHAR (PK) | 文件 ID |
| `user_id` | VARCHAR (FK) | 所属用户 |
| `storage_key` | VARCHAR (unique) | 前端稳定引用键，格式为 `backend:<id>` |
| `file_name` | VARCHAR | 原始文件名 |
| `content_type` | VARCHAR | MIME 类型 |
| `bytes` | BIGINT | 文件大小 |
| `relative_path` | VARCHAR | 相对 `USER_FILE_DIR` 的文件路径 |
| `created_at` | TIMESTAMP | 上传时间 |

### user_generation_logs 表

按用户保存图片和视频生成记录。创作端的生成历史通过账号接口增删改查，不再把 localforage 作为正常业务数据源。

| 列名 | 类型 | 说明 |
|---|---|---|
| `id` | VARCHAR (PK) | 后端记录 ID |
| `user_id` | VARCHAR (FK) | 所属用户 |
| `log_id` | VARCHAR | 前端生成记录 ID |
| `kind` | VARCHAR | 记录类型，目前为 `image` 或 `video` |
| `log_json` | TEXT | 生成记录完整 JSON |
| `created_at` | TIMESTAMP | 创建时间 |
| `updated_at` | TIMESTAMP | 最后更新时间 |

### user_generation_jobs 表

按用户保存画布生成请求的幂等任务响应。节点在调用模型前先保存稳定的 `generationJobId`；页面刷新或关闭后，前端使用同一 ID 重新请求，后端返回已经完成的原始响应，或等待仍在执行的同一请求，不会重复提交厂商任务。缓存记录保留 7 天。

| 列名 | 类型 | 说明 |
|---|---|---|
| `id` | VARCHAR (PK) | 后端任务记录 ID |
| `user_id` | VARCHAR (FK) | 所属用户 |
| `job_key` | VARCHAR | 节点保存的稳定任务 ID，与 `user_id` 联合唯一 |
| `status` | VARCHAR | `RUNNING`、`COMPLETED` 或 `FAILED` |
| `response_status` | INTEGER | 厂商代理响应的 HTTP 状态码 |
| `response_headers_json` | TEXT | 需要回放的响应头 |
| `response_body` | BLOB | 图片、文本、音频或任务创建响应的原始响应体 |
| `error_message` | TEXT | 后端执行异常 |
| `created_at` | TIMESTAMP | 创建时间 |
| `updated_at` | TIMESTAMP | 最后更新时间 |

### model_request_logs 表

记录经 `/api/model-runtime/models/*` 代理发出的每一次上游模型请求（创建 / 轮询 / 下载），用于在管理后台排查生成失败与超时原因。日志保留 7 天，写入失败不影响正常生成链路；错误信息会脱敏（URL 替换为 `[url]`）。

| 列名 | 类型 | 说明 |
|---|---|---|
| `id` | VARCHAR (PK) | 日志记录 ID |
| `user_id` | VARCHAR | 发起请求的用户（匿名代理为空） |
| `model_id` | VARCHAR | 后台注册的模型 ID |
| `method` | VARCHAR | 请求方法（POST / GET 等） |
| `path` | VARCHAR | 模型侧路径，如 `/videos`、`/videos/{id}`、`/chat/completions` |
| `request_kind` | VARCHAR | 请求方向：`create`、`poll`、`content`、`other` |
| `duration_ms` | BIGINT | 本次请求总耗时（毫秒） |
| `status_code` | INTEGER | 上游返回状态码（0 = 未得到响应） |
| `error_message` | TEXT | 失败 / 超时简要原因（已脱敏） |
| `job_key` | VARCHAR | 对应的画布任务 key |
| `created_at` | TIMESTAMP | 记录时间 |

管理后台查询接口：`GET /api/admin/model-request-logs`（仅管理员，支持 `modelId` / `statusCode` / `onlyErrors` / `page` / `size` 筛选）。

### 保存通道说明

- `backend`：正常业务唯一账号存储。登录并完成 bootstrap 后读写 `user_configs`、`canvas_projects`、`assets`、`user_files`、`user_generation_logs` 和 `user_generation_jobs`，不同账号数据隔离。未登录、工作区加载失败或后端不可用时，前端锁定用户页面，不回退浏览器数据。
- 浏览器 `localforage`：仅用于一次性旧数据迁移的传输缓存，不是可选择的保存模式。旧数据成功导入账号后，以后端账号工作区为权威。
