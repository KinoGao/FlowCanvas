# 画布数据结构

本文档说明当前画布在前端本地保存的数据结构、图片文件的存储和清理方式，以及后续接入后端存储时建议保持的兼容边界。

## 当前存储位置

画布与素材的权威数据保存在后端账号工作区：

- 画布项目、视角/背景等保存在后端 `canvas_projects`，随账号自动保存。
- 我的素材保存在后端 `assets`。
- 图片 / 视频 / 音频等媒体 Blob 上传到后端 `user_files`，节点只保存签名后的展示 URL 与 `storageKey`，真实媒体通过签名地址读取。
- 浏览器 `localforage` 仅用于一次性旧数据迁移与本地缓存，不是选择性的保存模式。

## 画布项目结构

每个画布项目是一个 `CanvasProject`：

```ts
type CanvasProject = {
  id: string;
  title: string;
  createdAt: string;
  updatedAt: string;
  nodes: CanvasNodeData[];
  connections: CanvasConnection[];
  nodeSequenceCounters: /* 类型级拆序号计数器 */;
  referenceOrderCounter: number;
  chatSessions: CanvasAssistantSession[];
  activeChatId: string | null;
  backgroundMode: "lines" | "dots" | "blank";
  connectionStyle: "curve" | "orthogonal" | "straight";
  inputPreference: { wheelMode: "zoom" | "pan"; wheelDirection: "normal" | "inverted" };
  showConnections: boolean;
  snapToGrid: boolean;
  alignmentGuidesEnabled: boolean;
  showImageInfo: boolean;
  viewport: { x: number; y: number; k: number };
  workflowTemplates: CanvasWorkflowTemplate[];
};
```

字段说明：

- `id`：画布项目 ID，前端生成，保存到后端随账号持久化。
- `title`：画布名称。
- `createdAt` / `updatedAt`：ISO 字符串。
- `nodes`：画布节点列表。
- `connections`：节点连线列表。
- `nodeSequenceCounters`：各节点类型的拆序号计数器，用于按类型编号。
- `referenceOrderCounter`：连线引用顺序计数器，用于 Composer / ComfyUI 输入条排序。
- `chatSessions`：右侧画布助手会话。
- `activeChatId`：当前选中的助手会话 ID。
- `backgroundMode`：画布背景模式。
- `connectionStyle`：连线样式（曲线 / 直角 / 直线），随画布项目持久化。
- `inputPreference`：画布输入偏好，普通滚轮/双指为缩放或 Figma 式平移，可切换缩放方向。
- `showConnections`：是否显示所有正式连线。
- `snapToGrid` / `alignmentGuidesEnabled`：网格吸附与辅助基准线开关。
- `showImageInfo`：是否显示图片尺寸信息。
- `viewport`：视口变换，`x/y` 是屏幕平移，`k` 是缩放比例。
- `workflowTemplates`：工作流工具箱保存的项目内模板。

## 节点结构

每个节点是一个 `CanvasNodeData`：

```ts
type CanvasNodeData = {
  id: string;
  type: "image" | "text" | "annotation" | "whiteboard" | "webpreview" | "video" | "audio" | "comfyui" | "group" | "config";
  title: string;
  position: { x: number; y: number };
  width: number;
  height: number;
  metadata?: CanvasNodeMetadata;
  pinColor?: string; // 节点 Pin 标记色，来自画布 Pin 色板 id
};
```

通用字段：

- `id`：节点 ID。
- `type`：节点类型，当前包括图片、文本、注释、白板、网页预览、视频、音频、ComfyUI、分组；`config` 仅用于兼容历史画布。
- `title`：节点标题。新节点按类型独立编号，用户可重命名。
- `position`：画布世界坐标，不是屏幕坐标。
- `width` / `height`：画布世界坐标下的节点尺寸。
- `pinColor`：节点的 Pin 颜色标记（右上角色点），对应画布 Pin 色板内的 id。
- `metadata`：节点内容和业务状态。
- `metadata.hidden`：节点管理面板隐藏标记，仅影响画布显示、连线和小地图，不影响保存与引用计算。

`metadata` 当前常用字段：

```ts
type CanvasNodeMetadata = {
  typeSequence?: number;
  hidden?: boolean;
  content?: string;
  prompt?: string;
  status?: "idle" | "success" | "loading" | "error";
  errorDetails?: string;
  fontSize?: number;
  generationMode?: "text" | "image" | "video" | "audio" | "comfyui";
  model?: string;
  size?: string;
  count?: number;
  naturalWidth?: number;
  naturalHeight?: number;
  freeResize?: boolean;
  isBatchRoot?: boolean;
  batchRootId?: string;
  batchChildIds?: string[];
  primaryImageId?: string;
  imageBatchExpanded?: boolean;
  storageKey?: string;
  mimeType?: string;
  bytes?: number;
};
```

不同节点的使用方式：

- 图片节点：`content` 是当前可展示的图片 URL，通常是 `blob:` URL；`storageKey` 指向本地图片 Blob；`naturalWidth/naturalHeight/bytes/mimeType` 保存原图信息。
- 视频节点：`content` 是当前可播放的视频 URL，通常是 `blob:` URL；`storageKey` 指向本地视频 Blob；`bytes/mimeType` 保存文件信息。
- 文本节点：`content` 保存文本内容；`fontSize` 保存字体大小；`prompt/status/errorDetails` 保存生成状态。
- ComfyUI 节点：`comfyWorkflowId/comfyFieldValues` 保存工作流和暴露参数；上游输入通过 `connections` 计算。历史 `config` 节点仍可读取和运行，但不再由新建入口创建。
- 图片组节点：根节点用 `isBatchRoot/batchChildIds/primaryImageId/imageBatchExpanded` 记录批量生成结果；子图节点用 `batchRootId` 指回根节点。

## 连线结构

每条连线是一个 `CanvasConnection`：

```ts
type CanvasConnection = {
  id: string;
  fromNodeId: string;
  toNodeId: string;
  referenceOrder?: number;
};
```

连线保存节点 ID 和可选的 `referenceOrder`，后者用于 Composer 与 ComfyUI 输入条按连线创建顺序展示引用；不保存端口坐标。渲染时根据节点位置和尺寸计算路径。

删除节点时会同步删除以该节点为起点或终点的连线。删除图片组根节点时，会把对应子节点一起删除。

## 助手会话结构

助手会话保存在画布项目内：

```ts
type CanvasAssistantSession = {
  id: string;
  title: string;
  messages: CanvasAssistantMessage[];
  createdAt: string;
  updatedAt: string;
};
```

消息结构：

```ts
type CanvasAssistantMessage = {
  id: string;
  role: "user" | "assistant";
  mode: "ask" | "image";
  text: string;
  isLoading?: boolean;
  references?: CanvasAssistantReference[];
  images?: CanvasAssistantImage[];
};
```

图片引用和助手生成图片也遵循同一套图片存储规则：

- `dataUrl` 字段当前可能是 `blob:` URL，也可能是旧数据中的 `data:image/...`。
- `storageKey` 存在时，以 `storageKey` 为准读取图片 Blob。
- 发送到 AI 接口前，如果接口需要 base64，会通过 `imageToDataUrl` 临时把 Blob URL 转成 data URL。

## 图片写入流程

在后端账号模式下，新增图片通过 `uploadImage(input)` 写入同步，媒体会经 `/api/user/files` 上传到后端 `user_files`，返回带签名地址的展示 URL 和 `backend:` 前缀的 `storageKey`：

1. 传入 `Blob` 或 data URL，内部统一转成 `Blob`。
2. 登录账号时调用 `uploadBackendFile` 上传到后端，得到签名 URL 与 `storageKey`（`backend:<id>`）。
3. 读取图片宽高，返回类似 `UploadedImage`（`url` / `storageKey` / `width` / `height` / `bytes` / `mimeType`）。

图片节点会写入：

```ts
{
  content: image.url,
  storageKey: image.storageKey,
  status: "success",
  naturalWidth: image.width,
  naturalHeight: image.height,
  bytes: image.bytes,
  mimeType: image.mimeType
}
```

因此，`content` 是带签名的可展示 URL，适合当前会话加载；长期标识是 `storageKey`。

未登录的遗留逻辑仍会用 `localforage` 的 `image_files` 存 Blob，但正常业务以后端账号工作区为权威。

## 图片读取和旧数据迁移

打开画布时会执行图片补水：

- 节点 `storageKey` 带 `backend:` 前缀时，通过 `resolveImageUrl` 向后端换签名 URL 展示；浏览器会话内尽量复用已解析的缓存。
- 旧数据中 `image:` 前缀的 `storageKey` 走 `localforage` 的 `image_files` 读取 Blob 生成 URL。
- 如果节点没有 `storageKey`,但 `content` 是旧的 `data:image/...`，会调用 `uploadImage(content)` 迁移并补上 `storageKey`。
- 助手消息里的引用图和生成图也会执行同类逻辑。

“我的素材”读取时也会做迁移，把旧 base64 / 本地 Blob 迁移到当前账号媒体。

## 图片移除和清理

后端账号下的媒体由后端账号工作区统一管理，画布删除时同步清理对应 `user_files` 引用。遗留本地 `image_files` 缓存仍通过引用清理回收，避免同一张图片被画布、素材或助手同时引用时误删。
