## 修复：720° 全景图导入后不显示 + 补齐轨道交互（用户第二次反馈）

用户实测：导入全景图后画面里看不到；并指出应好好对照 LibTV 导演台。

### 根因
`DirectorThreeStage` 没有持续渲染循环，`THREE.TextureLoader().load()` 异步加载全景贴图完成后没有任何代码触发 `renderer.render()`，导致全景球虽被创建但永不绘制。

### 修复点（均在 `canvas-client-page.tsx`）
1. **新增 rAF 渲染循环**：`mount` 内 `requestAnimationFrame(loop)` 持续运行；`needsRender` 标志 + `scheduleRender()` 触发单次重绘。
2. **全景纹理 onLoad 回调**：`TextureLoader().load(url, () => scheduleRender())` —— 贴图异步就绪后自动重绘。
3. **全景材质 `fog: false`**：场景 fog 远平面 42 而全景球半径 60，相机在球内时远处球面会被糊成背景色；关闭 fog 后全景清晰可见。
4. **补 OrbitControls**（LibTV 导演台可旋转/缩放/平移视角）：
   - 导入 `three/addons/controls/OrbitControls.js`，`mount` 时创建，阻尼 enabled，`maxPolarAngle` 限制不穿地，`min/maxDistance` 2~40。
   - 仅 `director` 视角启用；拖拽角色/机位时 `orbit.enabled=false`，`onPointerUp` 恢复；`rebuildScene` 重建时若正在拖拽（`drag.type` 非空）不重启用 orbit（否则拖角色时视角会跟着乱转）。
   - `rebuildScene` 末尾把 `orbit.target` 缓动到选中角色，rAF 循环里 `orbit.update()` 处理阻尼；cleanup `orbit.dispose()` + `cancelAnimationFrame`。
   - 「重置视角」按钮新增 `resetSignal` prop：`resetView` 时 `setResetSignal(v+1)` → 第三个 `useEffect` 把 orbit 相机/目标复位到默认（6,5.2,8.5）/（0,1.05,0）。通过 `scheduleRenderRef` 从外层 effect 触发重绘。
- `three@0.185.1` 自带 addons，`@types/three` 已提供 `examples/jsm/controls/OrbitControls.d.ts`，`three/addons/*` 是标准用法。

### LibTV 对照要点（来自知乎测评/抖音教程）
- 720° 全景：上传普通场景图可"一键转 720° 全景"，作为 3D 导演台的环境背景，旋转视角看不同角度；我们当前是直接导入 equirectangular 全景图（2D 图转真·全景需 AI outpainting，暂未做，用户反馈的是已导入全景图不显示，已修复）。
- 多角色：支持男/女/老/少/高/矮/胖/瘦素模 + 本地上传模型，可在线改名/改色/移位置/旋转/缩放，一键复制；我们已对齐 `type` 体型 + `scale` 缩放。
- 机位：导演视角选机位 → 切"机位视角"预览 → 截图得分镜参考；已对齐。

## 修复：导演台人物改为"真骨骼模型"（用户第三次反馈）

用户指出：LibTV 导演台的人物是**带骨骼的 3D 模型**，而我之前做的是球体+胶囊拼的几何体木偶，且当初调研没深挖"人物怎么渲染"。

### 调研结论（重新做了）
- LibTV 人物 = 真实 3D 人偶模型，支持**骨骼绑定 + 自由摆姿势**（B站官方教程《3D人偶绑定骨骼,导演台自由摆姿势》佐证）；支持本地上传自定义角色/道具。
- 我之前的 `addMannequin` 仅用 `Sphere/Capsule` + 刚体旋转，**无 Skeleton / SkinnedMesh / 骨骼 / IK**，属降级实现。

### 实现（均为 `canvas-client-page.tsx`）
1. **资源**：下载 Three.js 官方 `Xbot.glb`（CC0，自带完整 Mixamo 骨骼）到 `web/public/models/Xbot.glb`（2.8MB，合法 glTF）。
   - 经解析确认：Xbot 以**厘米**为单位（包围盒高 177.75 three 单位）、静止为 **T-pose**（骨骼旋转全 identity）、骨骼名带冒号（`mixamorig:Head` 等）。→ 需缩放 `0.01` 落到米制场景（~1.78 单位高），且手臂基准角用 ±90° 从 T-pose 落到体侧。
2. **加载**：模块级缓存 `loadDirectorModel()`（`GLTFLoader` 加载 `/models/Xbot.glb`，memoize）；`mount` 时触发，就绪后 `rebuildRef.current()` + `scheduleRender()` 重建并刷新。`cachedDirectorModel` 全局缓存，多 mount 不重复下载。
3. **多角色克隆**：`buildRiggedCharacter()` 用 `SkeletonUtils.clone`（**必须用**，否则多角色共用同一副骨骼导致串味），每片 mesh `material.clone()` 并按 `char.color` 着色，选中时加 `emissive` 高亮；`clone.scale.setScalar(0.01)` 归一化尺寸。
4. **姿势驱动骨骼**：`applyDirectorPose()` 将 pose 参数映射到 Mixamo 骨骼（`mixamorig:Head/Neck/Spine/LeftArm/RightArm/LeftUpLeg/RightUpLeg`，带别名回退）；`addDirectorPoseHandles()` 在头/双手加可拖拽姿势手柄（沿用原 pose 拖拽逻辑）。
5. **占位兜底**：模型未就绪时仍用 `addMannequin` 几何体人偶，避免空场景；加载完成后自动替换为真骨骼。
6. **体积比例**：`TYPE_FACTORS` 改为**单值 uniform 缩放**（避免非均匀缩放剪切蒙皮网格），`male/female/child/tall/short/heavy/slim` 各一系数，配合 `char.scale` → 不同比例角色同框（对齐 LibTV"机甲 1.7× 主角"卖点）。

### 实施陷阱（已规避）
- Xbot 骨骼名是 `mixamorig:Head` 不是 `mixamorigHead`（无冒号会静默匹配失败 → 姿势不生效）。
- Xbot 厘米单位，不缩放会大到撑爆场景（177 单位）。
- 蒙皮网格多实例必须用 `SkeletonUtils.clone`，直接 `.clone()` 共享骨骼。

### 待用户本地验证（未跑 build）
- 手臂/腿部基础角 ±90° / ±90° 的符号基于 Xbot 骨骼朝向推导，若可视化发现手臂外翻/上举，翻转 `applyDirectorPose` 中左右臂 base 角符号即可（单点修改）。
- 姿势手柄位置（头/双手）为组局部坐标近似值，可能需微调。
- 每次 pose/位置变更 `rebuildScene` 会重新 `SkeletonUtils.clone`，多角色时若拖拽卡顿可改为按 characterId 缓存 clone。

## 紧急修复：人物完全不可见（用户第四次反馈"人呢？"）

### 根因（已用 Node 实证，不是猜）
Xbot.glb 的网格顶点存在"局部小空间"，**真实尺寸靠骨骼蒙皮撑开**。实测：
- `Box3.setFromObject(clone)`（不套蒙皮）→ 包围盒仅 ~0.02 单位（误导我以为模型是厘米单位、高 177）。
- `SkinnedMesh.computeBoundingBox()`（套蒙皮）→ **真实高 1.81 单位**（已是正确米制尺寸）。
我据此把 `DIRECTOR_MODEL_SCALE` 硬编码成 `0.01`，把本就正确的 1.81 单位模型又缩了 100 倍 → 0.018 单位 → 肉眼不可见。这就是"人没了"的真正原因。

### 修复（均为 `canvas-client-page.tsx`）
- **删除硬编码 `0.01`**，改为加载时 `computeModelScale(gltf)`：用 `cloneSkeleton` 探针 + `probe.updateMatrixWorld(true)` + 每个 `SkinnedMesh.computeBoundingBox()`（套蒙皮）测真实高度，归一化到 `1.8 / h`。结果存入模块级 `cachedDirectorModelScale`，`buildRiggedCharacter` 用它。这样换任何 rigged 模型都不会再因单位假设缩没。
- 顺手修了 `buildRiggedCharacter` 的两处隐患：① 每片 mesh `frustumCulled = false`（缩放后包围盒过期被视锥裁掉的风险）；② 材质处理支持 `Material[]` 数组（多材质 mesh 不会被错误转型导致不渲染）。

### 教训（务必记住）
- **rigged 模型的"身高"必须靠蒙皮后测量，绝不能把骨骼 translation 之和当天生高度**。加载后用 `SkinnedMesh.computeBoundingBox()` 测真实包围盒再决定缩放。
- 下次导入任何 GLB 角色，先按此法测一次真实尺寸，再写缩放，别拍脑袋。

## 修复：改姿势参数整个界面乱跑（用户第五次反馈）

### 根因
`rebuildScene` 末尾每次都执行 `orbit.target.lerp(targetPos, 0.25)`，而 `rebuildScene` 在**任何** prop 变化（含改姿势/位置/缩放）时都触发。加上 rAF 循环里 `orbit.update()` 始终运行（不检查 `enabled`），导致每次拖姿势都把相机焦点往角色拽 25% → 画面乱跑。

### 修复（`canvas-client-page.tsx`）
1. **相机焦点改为"仅切换选中角色时 snap"**：闭包变量 `lastFocusId` 记录上次聚焦角色 id，只在 `focusId !== lastFocusId` 时 `orbit.target.copy(targetPos)`（一次性 snap 不 lerp）。改姿势/位置/缩放不再移动相机。
2. **全景贴图按 URL 缓存**：`panoTex`/`panoTexUrl` 闭包变量，URL 不变就复用已有 Texture，不再每次 rebuild 都重建 GPU 纹理。

### 待办（若用户反馈多角色仍卡顿）
- 每次 rebuild 仍对所有角色跑 `SkeletonUtils.clone`（12 角色 × ~2ms ≈ 24ms/rebuild）。若拖姿势仍卡，改"克隆复用"：角色组从 contentGroup 摘出不参与销毁，已有角色直接更新骨骼/颜色/手柄，只对新增角色克隆。

## 修复：右侧面板滚动 + 拖拽不稳定 + 卡顿

### 三个根因
1. **右侧面板不能滚动**：18 滑块+20 预设太长，面板没 `overflow-y-auto`。修：加 `thin-scrollbar overflow-y-auto`。
2. **人偶拖拽不稳定**：SkinnedMesh 射线检测基于 T-pose 几何体，摆姿后可见位置和检测位置对不上。修：每个角色加不可见透明圆柱代理碰撞体（`opacity:0` 可被 raycaster 命中）。
3. **卡顿**：每次 rebuild 对所有角色 `SkeletonUtils.clone`。修：**克隆复用** — 已有角色调 `updateRiggedCharacter` 只更新 pose/颜色/手柄，只对新增角色克隆。

### 骨骼名冒号 bug（根因之二：预设姿势全部失效）
GLTFLoader 加载后 Mixamo 骨骼名**无冒号**（`mixamorigHead` 不是 `mixamorig:Head`）。曾误补冒号导致 findBone 全部返回 null、20 个预设无一生效。已修正：全局去冒号（15 处）。肘部(ForeArm)弯曲用 Z 轴不是 X 轴（实测）。

### 克隆复用 + 人偶兜底冲突 bug（已修）
首次 rebuild 模型没加载完→走 addMannequin 占位→group 存入 characterGroups。模型加载后 rebuild→复用 group→`updateRiggedCharacter` 找 `isRig` 找不到（人偶没有）→**人偶永远不会被替换成骨骼模型**（用户看到球体胶囊木偶而非 Xbot）。修：复用时检查 `group.children.some(c => c.userData.isRig)`，无 rig 且模型已加载→销毁人偶→`buildRiggedCharacter` 重建。

### "Maximum update depth exceeded" 崩溃（已修）
拖拽角色/道具/机位/姿势时，`onPointerMove` 每次 mousemove 都调 `onChange`→`setNodes`→React Flow `StoreUpdater` 同步。高频 setNodes 触发 StoreUpdater 内部循环→React 判定 "Maximum update depth exceeded"。修：**rAF 节流**——`scheduleChange(fn)` 把 onChange 回调存入 `pendingChange`，每帧最多 flush 一次（`requestAnimationFrame`）。拖拽时的 4 个 onChange（角色位置/道具位置/机位位置/姿势变更）全部包进 `scheduleChange`。cleanup 加 `cancelAnimationFrame(changeRafId)`。
